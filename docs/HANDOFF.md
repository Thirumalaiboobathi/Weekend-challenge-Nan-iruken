# HANDOFF - Naan Irukken (AWS Builder Center Serverless Weekend Challenge)
Deadline Mon Nov 16 1 PM PT (Tue 02:30 IST). Daily Telegram check-in for elderly parents; no reply -> escalate to family.

## Constraints
Serverless only, ap-south-1, SAM. Python 3.12 arm64, boto3 + stdlib only (Telegram via urllib). No Docker/sam local: test on the deployed stack.
Windows 11 PowerShell, quote paths with spaces. `sam validate --lint` before every deploy. Never print secrets; user runs scripts\put_secrets.ps1 themselves (never ask for the bot token).
Per-function least-privilege IAM. Demo timeouts come in the execution input, never hardcoded in ASL.

## Architecture (docs/architecture.md has the Mermaid diagram)
Telegram -> HttpApi POST /telegram/webhook -> BotHandler (secret header, always 200) -> Step Functions STANDARD.
Lambdas: BotHandler (src/bot_handler: app.py commands, buttons.py taps), LoadProfile, Notify (table-driven STAGES), LogResult. Shared: src/shared (db, checkin, telegram).
One DynamoDB table `NaanIrukken` (PK/SK, TTL attr `ttl`). Task token lives ONLY in DynamoDB; buttons carry `kind:shortId`.
Stack naan-irukken; bot @naanirukken_thiru_bot; admin id 1276258406. Secrets in SSM /naan-irukken/*.

## State machine (statemachine/checkin.asl.json is GENERATED by scripts/dev/gen_asl.py; run from project root)
Init(reesc n=0) > LoadProfile > CheckPaused > PingParent > CheckPing / RemindParent > CheckRemind / AlertContact1 > CheckContact1 / AlertContact2 > CheckContact2 / AlertAll(plain) > LogResult.
Urgent: UrgentAlert > UrgentAlert2 > ParentEmergency (112/108 to parent) > LogResult (help_unclaimed). Never AlertAll.
Claim: AwaitConfirmation (confirm) > CheckConfirm (needs_help > EmergencyAlert) > BumpReescalation > limit n<=2 > ReEscalate > AwaitConfirmation; else AlertAll.
Wait states use waitForTaskToken + TimeoutSecondsPath; Catch States.Timeout -> next stage, States.ALL -> LogResult.
Task output status: ok | help | claimed | fine | needs_help.
Callback prefixes: ok: parent fine, help: SOS, ack: contact claims, cf:/cn: claimer fine/needs help (stage confirm, claimer only).
Outcomes: resolved, escalated, confirmed_safe, needs_help, help_unclaimed, skipped, error.

## DynamoDB shapes
USER: PK=USER#<id>, SK=PROFILE: name, chatId, lastSeen, streak, activeCheckinId, pausedUntil. Contacts via checkin.contacts_for (admin stands in as "[as Contact #N]" when DEMO_MODE).
CHECKIN: PK=CHECKIN#<execName>, SK=META: userId, stage, activeToken ("-" = nothing waiting), activeShortId, openMsgs[], helpAt, claimedBy, claimedById, confirmedBy, reescalations, outcome, stageReached, timeline[], finishedAt, ttl.
`events` list on CHECKIN (list_append): {t, type, actor, role, via, stage[, detail]}; types sent|timeout|checkin|help|claim|confirm|reescalate|late_help|finished. Source of truth for Phase 4 audit.
SHORTID: maps short id -> check-in.
